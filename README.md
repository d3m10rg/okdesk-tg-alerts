# Okdesk → Telegram alerts

Контейнерный Python-бот для мониторинга новых заявок в
[`sd.cpsupport.ru`](https://sd.cpsupport.ru/) (Okdesk). Бот входит через
официальный REST API под указанными логином и паролем и публикует новые заявки
в Telegram-канал.

```text
№ заявки: 12345
Название: Не работает касса
Уровень: высокий
```

Поддерживаемые уровни: `низкий`, `обычный`, `высокий`, `критикал`.

## Как исключаются ложные алерты

- Первый запуск только фиксирует текущую верхнюю границу и не рассылает старые
  заявки.
- Курсор номера движется только вверх и никогда не уменьшается после удаления
  или объединения заявки.
- Каждый новый последовательный номер проверяется отдельно. Удалённый,
  объединённый или недоступный номер пропускается.
- В состоянии хранится один курсор и до девяти предыдущих полученных номеров —
  суммарно не более 10 номеров заявок.
- Большой накопившийся диапазон разбирается порциями без загрузки полной истории
  в память.

Если процесс завершится ровно после успешной отправки в Telegram, но до записи
состояния, после перезапуска возможно одно повторное сообщение. Это сделано,
чтобы не потерять уведомление.

## Подготовка Telegram-канала

1. Создайте бота через `@BotFather` и сохраните токен.
2. Добавьте бота администратором канала с правом публикации сообщений.
3. Определите адрес назначения:
   - для публичного канала можно использовать `@channel_name`;
   - для частного канала нужен числовой ID вида `-1001234567890`.

Числовой ID частного канала можно получить через пересланное сообщение или
временный вызов `getUpdates` до запуска этого контейнера.

## Установка на сервер

Требуются Git, Docker и Docker Compose.

```bash
git clone https://github.com/d3m10rg/okdesk-tg-alerts.git
cd okdesk-tg-alerts
cp .env.example .env
nano .env
chmod 600 .env
docker compose up -d --build
docker compose logs -f okdesk-monitor
```

Минимальная конфигурация `.env`:

```dotenv
OKDESK_URL=https://sd.cpsupport.ru
OKDESK_LOGIN=your_login
OKDESK_PASSWORD=your_password
TELEGRAM_BOT_TOKEN=123456789:replace_me
TELEGRAM_CHAT_ID=-1001234567890
```

Для публичного канала последнюю строку можно заменить на:

```dotenv
TELEGRAM_CHAT_ID=@channel_name
```

После первого успешного цикла в журнале появится `Initial baseline saved`.
Уведомления начнут приходить только для заявок, появившихся после этой точки.

## Локальное меню отладки

Отладка и смена реквизитов выполняются только в терминале сервера. Telegram
используется исключительно для публикации алертов в канал.

Откройте меню внутри работающего контейнера:

```bash
docker compose exec okdesk-monitor python -m app.admin
```

Меню позволяет:

1. просмотреть до 10 последних реально полученных номеров и текущий курсор;
2. изменить логин Okdesk;
3. изменить пароль Okdesk;
4. одновременно изменить логин и пароль.

Пароль вводится через скрытый терминальный prompt. Новые данные сначала
проверяются запросом авторизации к Okdesk и только затем атомарно записываются в
`/data/credentials.json` с правами `0600`. Рабочий процесс увидит изменение в
следующем цикле опроса; перезапуск контейнера не требуется.

Сохранённые через меню значения имеют приоритет над `.env` после последующих
перезапусков контейнера. Содержимое файла с реквизитами не выводится в журнал.

## Управление

Посмотреть журнал:

```bash
docker compose logs -f okdesk-monitor
```

Перезапустить:

```bash
docker compose restart okdesk-monitor
```

Обновить из GitHub:

```bash
git pull --ff-only
docker compose up -d --build
```

Остановить:

```bash
docker compose down
```

Состояние и изменённые через серверное меню реквизиты находятся в именованном
Docker volume `okdesk-state`. Команда `docker compose down` сохраняет volume.
Не используйте `docker compose down -v`, если не хотите удалить стартовую точку
и сохранённые через меню данные.

## Проверка одним циклом

```bash
docker compose run --rm okdesk-monitor python -m app.main --once
```

Первый запуск создаёт стартовую точку. Повторный запуск проверяет новые номера и
завершается.

## Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `OKDESK_URL` | Адрес аккаунта Okdesk | `https://sd.cpsupport.ru` |
| `POLL_INTERVAL_SECONDS` | Интервал проверки | `60` |
| `REQUEST_TIMEOUT_SECONDS` | Таймаут внешнего запроса | `30` |
| `MAX_ISSUES_PER_CYCLE` | Максимум последовательных номеров за цикл | `100` |
| `STATE_PATH` | Состояние монитора | `/data/state.json` |
| `CREDENTIALS_PATH` | Изменённые через меню данные | `/data/credentials.json` |
| `LOG_LEVEL` | Уровень журнала | `INFO` |

Для секретов поддерживаются файловые варианты `OKDESK_LOGIN_FILE`,
`OKDESK_PASSWORD_FILE`, `TELEGRAM_BOT_TOKEN_FILE` и `TELEGRAM_CHAT_ID_FILE`.
Нельзя одновременно задавать обычную переменную и соответствующую `_FILE`.
